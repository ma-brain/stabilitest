# Simulation CLI and Canonical Results Design

## Context

`manuscript/simulation_study.R` can now locate and load the current package
checkout, but direct execution does not run the simulation because the only
execution block is guarded by `interactive()`. The manuscript nevertheless
instructs readers to launch the script with `Rscript`. The script also omits
the score standard deviation displayed in Section 3.2, does not pass its
`n_boot` setting through `run_simulation()`, and has no machine check tying
archived results to the manuscript tables.

The canonical study is twelve scenarios: three effect sizes, two group sizes,
and two contamination settings, with 500 replications and 200 bootstrap
iterations per replication. It takes roughly one to two hours single-threaded.

## Goals

- Make a bare `Rscript manuscript/simulation_study.R` invocation run the
  canonical study exactly once.
- Write canonical output beside the script as
  `manuscript/simulation_results.csv`, independent of the caller's working
  directory.
- Provide explicit overrides and a safe smoke mode for development.
- Preserve source-only use: `source("simulation_study.R")` defines functions
  without starting a simulation.
- Archive sufficient parameters and summary statistics to reproduce both
  simulation tables.
- Update manuscript values to the canonical deterministic run and fail a
  machine check whenever the CSV and published tables diverge.
- Regenerate the tracked manuscript PDF from the synchronized Markdown.

## Non-goals

- Parallelizing or changing the statistical simulation algorithm.
- Resuming interrupted runs or maintaining per-scenario checkpoints.
- Calibrating non-Welch engines.
- Moving the manuscript workflow into `targets`, Make, or an installed package
  command.

## CLI Contract

The script will use a small base-R parser, avoiding a new package dependency.
It supports:

```text
--nrep N       positive integer replications per scenario
--n-boot B     positive integer bootstrap iterations per replication
--output PATH  CSV destination
--smoke        use nrep = 2 and n_boot = 10
--help         print usage and exit without running
```

With no arguments, defaults are `nrep = 500`, `n_boot = 200`, and an output
path of `simulation_results.csv` in the script's directory. Smoke mode defaults
to `simulation_results_smoke.csv`, so it cannot overwrite canonical output.
An explicit `--output` always wins. To keep behavior unambiguous, `--smoke`
cannot be combined with `--nrep` or `--n-boot`.

Unknown options, missing values, non-integer or non-positive counts, duplicate
options, and an unusable output directory fail before any scenario begins with
an actionable error. `--help` cannot be combined with run options.

The script will distinguish direct `Rscript` execution from `source()` by
comparing the normalized `--file=` argument with its own resolved path. Only a
direct match enters the CLI runner.

## Simulation and Output Flow

`run_simulation()` will accept and forward both `nrep` and `n_boot`. Each
scenario remains seeded independently with `987000 + scenario`, preserving
determinism across sequential runs.

Each of the twelve output rows will contain:

- scenario design and provenance: `nrep`, `n_boot`, `scenario_seed`, `d`,
  `n_per_group`, and `n_outliers`;
- all-replication summaries: `rejection_rate`, `score_all`, and
  `score_all_sd`;
- significance-conditional summaries: `score_sig`, `score_nonsig`,
  `k_wc_med_sig`, `frag_wc_med_sig`, `k_ex_med_sig`, `s_jack_sig`, and
  `s_boot_sig`.

The CLI will write to a temporary file in the destination directory and rename
it into place only after all scenarios finish. A failed or interrupted run
therefore cannot replace a previously valid canonical CSV with partial output.

## Manuscript Synchronization

After the canonical run, the tracked CSV becomes the numerical source for
Sections 3.2 and 3.3. The manuscript tables will be updated to the archived
values at their published precision:

- rejection rate: three decimals;
- score means, score SD, fragility percentage, jackknife stability, and
  bootstrap reproducibility: one decimal;
- median removal counts: integers;
- missing conditional summaries: em dash.

`manuscript/check_simulation_results.R` will read the CSV, render the expected
Markdown row strings for both tables, and verify that every expected row occurs
exactly once in the corresponding manuscript section. It will also validate
the CSV schema, twelve-scenario key, canonical `nrep`, canonical `n_boot`, and
scenario seeds. The checker fails clearly on missing, duplicated, malformed,
or stale results.

The manuscript text will say the tables were generated by the exact tracked
script and archived CSV, replacing the current "algorithmically identical"
qualification. `manuscript/build_pdf.sh` will regenerate the tracked PDF after
the Markdown tables are synchronized.

## Testing

The standalone simulation entry-point smoke test will cover:

- sourcing defines functions without creating an output file;
- parser defaults select 500 replications, 200 bootstraps, and the canonical
  path;
- `--help` exits successfully without running;
- invalid, missing, duplicate, conflicting, and unknown options fail clearly;
- a direct reduced run with explicit `--nrep 1 --n-boot 2 --output <temp>`
  writes twelve rows with the required schema and parameters;
- `--smoke` selects its separate output name.

The result checker will first be run against a deliberately stale fixture to
prove it fails, then against the canonical full-run CSV and synchronized
manuscript to prove it passes. Final verification includes the simulation smoke
test, result/manuscript check, full package tests, regenerated PDF inspection,
`git diff --check`, and clean source-archive `R CMD check`.
